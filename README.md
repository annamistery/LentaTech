# LentaTech

Распознавание ценников в режиме реального времени для сети гипермаркетов **«Лента»**. Проект строит полный пайплайн от zero-shot авторазметки по видео до инференса, трекинга, нарезки ценников и подготовки данных для мультимодальной модели ZwZ-8B на базе qwen-VL3. Архитектура проекта централизует пути, параметры и логирование через `config.py` и `logging_setup.py`, что соответствует хорошей практике для Python-проектов с несколькими исполняемыми модулями.[cite:277][cite:401]

## Что делает проект

Система предназначена для автоматического поиска ценников на полках магазинов, подготовки обучающего датасета и дальнейшего извлечения визуальных фрагментов ценников для распознавания их содержимого. В основе лежит двухэтапный подход: сначала zero-shot детекция Grounding DINO для быстрой первичной разметки, затем обучение YOLO-модели для быстрого и стабильного детекта на реальных видео.[cite:247][cite:402]

Основные задачи проекта:

- Автоматически размечать видео без ручной полной аннотации.
- Формировать датасет в YOLO-формате.
- Очищать датасет после ручной проверки.
- Обучать детектор ценников.
- Выполнять инференс в реальном времени.
- Вырезать найденные ценники в отдельные изображения.
- Формировать поток данных для дальнейшего OCR / VLM-распознавания через Qwen 3.6.

## Пайплайн обработки

Ниже описан фактический порядок работы модулей в репозитории.

### 1. `dino.py` — zero-shot авторазметка

Скрипт `dino.py` использует Grounding DINO для zero-shot детекции ценников на кадрах из входных видео. На этом этапе из видео извлекаются кадры, фильтруются нерезкие и слишком тёмные изображения, строятся bounding boxes ценников и создаются файлы разметки в текстовом формате, совместимом с YOLO-датасетом.[cite:247][cite:402]

Что делает модуль:

- читает входные видео из каталога с сырьём;
- извлекает кадры с заданным шагом;
- применяет zero-shot детекцию по текстовому промпту;
- фильтрует некачественные и нерелевантные боксы;
- сохраняет изображения, `.txt`-разметку и служебные метаданные;
- формирует обучающую и валидационную выборки.

Результат этапа:

- `images_all/` — все принятые кадры;
- `labels_all/` — все bounding boxes в YOLO-формате;
- `images/train`, `images/val` — train/val изображения;
- `labels/train`, `labels/val` — train/val разметка;
- `vis/` — визуализации для ручной проверки;
- `meta/` — дополнительные JSON-метаданные;
- `data.yaml` — датасет для обучения YOLO.

### 2. `cleanup_after_review.py` / `cleaning_data.py` — очистка датасета после ручной проверки

После генерации визуализаций из `vis/` вручную отбираются годные и негодные кадры. Скрипт очистки удаляет нерелевантные изображения, текстовые координаты рамок и сопутствующие файлы, которые больше не имеют подтверждения после ручной проверки.[cite:388][cite:389]

Что делает модуль:

- собирает валидные ключи по файлам из `vis/`;
- ищет «сироты» в `images_all`, `labels_all`, `meta`, `images/train`, `images/val`, `labels/train`, `labels/val`;
- делает dry-run отчёт;
- при включённом флаге удаляет лишние файлы;
- при необходимости обновляет `pipeline_stats.json`.

Этот этап нужен, чтобы не тянуть в обучение шумные кадры, ошибочные боксы и мусор после zero-shot разметки.[cite:388][cite:390]

### 3. `yolo12.py` — обучение модели YOLO12S

Очищенный датасет передаётся в модуль обучения `yolo12.py`. Скрипт запускает обучение локальной YOLO-модели на сформированном датасете, использует конфигурацию аугментаций, сохраняет промежуточные веса и итоговую сводку по обучению.[cite:345][cite:343]

Что делает модуль:

- проверяет структуру датасета и наличие всех папок;
- переписывает `data.yaml` в консистентный вид;
- подгружает локальные веса базовой модели;
- запускает обучение на train/val;
- сохраняет веса `best.pt` и `last.pt`;
- валидирует лучшую модель;
- записывает `training_summary.json`.

На выходе получается обученный детектор ценников, который используется на следующих этапах.

### 4. `inference_yolo.py` — детекция ценников на лету

Скрипт `inference_yolo.py` выполняет инференс обученной модели на видео или веб-камере. Порог уверенности задаётся конфигурацией или через CLI, а результат может одновременно отображаться в окне и сохраняться в выходной видеофайл.[cite:356][cite:345]

Что делает модуль:

- загружает обученную YOLO-модель;
- запускает предсказание по кадрам;
- отрисовывает bounding boxes и confidence;
- показывает FPS и базовую статистику;
- сохраняет итоговое видео с детекциями.

Это основной блок для онлайн-распознавания ценников в реальном времени.

### 5. `crop_price.py` — нарезка ценников по рамкам

Скрипт `crop_price.py` использует обученную модель для поиска ценников на изображениях и видео, а затем вырезает найденные области в отдельные файлы. Это удобно для последующего OCR, классификации или передачи в мультимодальную модель.[cite:356][cite:278]

Что делает модуль:

- обрабатывает папку с изображениями и видео;
- выполняет детекцию ценников;
- добавляет padding вокруг найденного бокса;
- отбрасывает слишком маленькие crop-области;
- сохраняет вырезанные ценники как отдельные `.jpg`.

Такие кропы можно использовать как самостоятельный вход для последующих блоков анализа содержимого ценника.

### 6. `traker.py`  — трекинг и генератор кадров ценников

Трекинговый модуль использует YOLO + ByteTrack для устойчивого сопровождения ценников между кадрами видео. В проекте этот этап нужен не только для визуализации треков, но и как генератор последовательности изображений по детектированным ценникам для дальнейшей подачи в мультимодальную модель Qwen 3.6.[cite:247][cite:356]

Что делает модуль:

- детектирует ценники на каждом кадре;
- сопоставляет детекции между соседними кадрами;
- присваивает `tracker_id`;
- сохраняет аннотированное видео;
- формирует поток устойчивых crop-областей для последующего распознавания текста и атрибутов ценника.

### 7. `lenta_vision` — подача в мультимодальную систему

После детекции, трекинга и нарезки ценников данные передаются в блок `lenta_vision`. На этом уровне ценники становятся входом для дальнейшей мультимодальной обработки, где модель семейства Qwen 3.6 распознаёт содержимое ценника: текст, цену, сопутствующую информацию и другие визуально значимые поля.[cite:247]

## Архитектура репозитория

```text
LentaTech/
├── config.py

├── dino.py
├── cleanup_after_review.py
├── yolo12.py
├── inference_yolo.py
├── crop_price.py
├── traker.py
├── lenta_vision/

├── logs/

    └── dataset/
        ├── data.yaml
        ├── images_all/
        ├── labels_all/
```

Проект использует единый `config.py` для путей, порогов и параметров обучения/инференса, а `logging_setup.py` централизует логирование по модулям. Такая структура помогает держать многошаговый пайплайн в согласованном состоянии.[cite:277][cite:401]

## Основные зависимости

Ниже перечислены ключевые библиотеки, которые используются в проекте.

| Библиотека | Назначение |
|---|---|
| `torch` | Бэкенд для инференса и обучения нейросетей. |
| `ultralytics` | Обучение, инференс и трекинг моделей YOLO.[cite:343][cite:356] |
| `opencv-python` (`cv2`) | Работа с видео, кадрами, визуализацией и сохранением изображений. |
| `numpy` | Обработка координат, массивов и геометрии боксов. |
| `tqdm` | Прогресс-бары в долгих операциях. |
| `supervision` | Аннотация, структуры `Detections`, интеграция с ByteTrack. |
| `pathlib` | Единая работа с файловыми путями в проекте.[cite:278][cite:277] |
| `json` | Сохранение отчётов, метаданных и статистики пайплайна. |

Дополнительно для zero-shot этапа требуется локальная или установленная среда Grounding DINO, а для дальнейшего распознавания содержимого ценников используется мультимодальная модель Qwen 3.6 в модуле `lenta_vision`.

## Требования к окружению

Рекомендуемая среда:

- Python 3.10+;
- CUDA-совместимая GPU для обучения и быстрого инференса;
- локально доступные веса моделей;
- Windows или Linux с корректно установленными `torch`, `opencv-python`, `ultralytics` и зависимостями Grounding DINO.

Минимальный пример установки:

```bash
pip install torch torchvision torchaudio
pip install ultralytics supervision opencv-python tqdm numpy
```

Если используется отдельный модуль Grounding DINO или мультимодальный стек для Qwen, их зависимости устанавливаются отдельно в соответствии с их документацией.

## Быстрый старт

### 1. Подготовить окружение

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -U pip
pip install torch torchvision torchaudio
pip install ultralytics supervision opencv-python tqdm numpy
```

### 2. Проверить конфигурацию

В файле `config.py` нужно проверить:

- каталоги проекта;
- пути к входным видео;
- пути к весам YOLO;
- параметры DINO, train, inference, crop, tracker;
- флаги cleanup.

### 3. Сформировать датасет

```bash
python dino.py
```

### 4. Очистить датасет после ручной проверки

Сначала выполнить dry-run:

```bash
python cleanup_after_review.py
```

После проверки включить удаление в `config.py`:

```python
CLEANUP_DO_DELETE = True
```

и повторно запустить очистку.

### 5. Обучить YOLO

```bash
python yolo12.py
```

### 6. Выполнить инференс

```bash
python inference_yolo.py
```

Или с параметрами:

```bash
python inference_yolo.py --video path/to/video.mp4 --conf 0.4 --iou 0.45 --no-show
```

### 7. Нарезать ценники

```bash
python crop_price.py
```

### 8. Запустить трекинг

```bash
python traker.py
```

## Логирование

Проект использует централизованный модуль `logging_setup.py`. Каждый исполняемый файл создаёт собственный именованный logger и пишет сообщения в консоль и в отдельный файл логов, что упрощает отладку длинного пайплайна и воспроизводимость прогонов.[cite:401][cite:255]

## Выходные артефакты

В зависимости от этапа проект создаёт:

- train/val датасет в YOLO-формате;
- визуализации детекций для ручной проверки;
- JSON-метаданные и статистику пайплайна;
- обученные веса `best.pt` и `last.pt`;
- видео с результатами инференса;
- crop-изображения ценников;
- трекинговое видео и последовательности изображений для мультимодальной обработки.

## Применение результата

Итоговая модель используется как первый визуальный этап в более широком пайплайне `lenta_vision`. Сначала система быстро находит ценник на полке, затем выделяет соответствующую область, а после этого более тяжёлая мультимодальная модель извлекает из ценника полезную информацию для downstream-задач анализа ассортимента, цен и состояния полочного пространства.[cite:247]

## Ограничения

- Качество датасета на старте зависит от zero-shot разметки Grounding DINO.
- Без ручной очистки в обучающую выборку может попадать шум.
- Качество детекции зависит от освещения, резкости, угла съёмки и плотности выкладки.
- Для реального времени желательна GPU.
- Для полноценного распознавания содержимого ценника одного детектора недостаточно — нужен следующий OCR/VLM-этап.
